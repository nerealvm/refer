$root и $parent

Вопрос из списка: «Осторожность использования $root и $parent»

Суть. $parent и $root дают прямой доступ к чужому компоненту в обход props и событий. Это скрытая связь: компонент ломается при переносе в другое место дерева, а изменения данных трудно отследить. Поэтому вместо них используют props и $emit, provide/inject или Vuex.

this.$parent — экземпляр родительского компонента. this.$root — корневой экземпляр new Vue(). Через них можно читать и менять чужие данные и вызывать чужие методы в обход props и событий.

Почему это опасно

  • Скрытая связь. Ребёнок знает внутреннее устройство родителя: имена полей и методов. Переименовали поле в родителе — ребёнок сломался молча, без ошибки.
  • $parent зависит от места в дереве. Обернули компонент в другой компонент или передали в слот — $parent стал другим. Абстрактные <keep-alive> и <transition> в цепочку не попадают.
  • Ломается однонаправленный поток данных. Данные меняются откуда угодно — трудно найти, кто их поменял.
  • $root как глобальное хранилище ненадёжен. Поля, которых не было в data корня при создании, не реактивны, и добавить их потом нельзя.
  • Компонент нельзя переиспользовать и тестировать отдельно: в другом месте у него другой родитель и другой корень.

Чем заменить. Данные вниз — через props, наверх — через $emit (сюда же v-model и .sync). Для глубокой вложенности — provide/inject. Для общего состояния приложения — Vuex.

Когда допустимо. Тесно связанные пары внутри библиотеки компонентов (Tabs/Tab, Table/Column, Map/Marker) и быстрые прототипы.

Пример
// плохо: ребёнок сам лезет в чужие данные
this.$parent.count++;
this.$root.user.name = 'Аня';

// хорошо: ребёнок сообщает, родитель решает
this.$emit('increment');
// в шаблоне родителя: <Child @increment="count++" />

1.1 $parent в слоте 🟢 базовый ~3 мин

Кнопка PlusButton меняет count через $parent. В слоте Panel такая же кнопка молча не работает. Объясни, чей там $parent, и перепиши: кнопка только сообщает о клике.

Стартовый код
const PlusButton = {
  template: '<button @click="add">+1</button>',
  methods: { add() { this.$parent.count++ } },
}
const Panel = { template: '<section><slot></slot></section>' }
const component = {
  components: { PlusButton, Panel },
  data: () => ({ count: 0 }),
  template: '<div><PlusButton /><Panel><PlusButton /></Panel><span>{{ count }}</span></div>',
}
// нужно: каждая из двух кнопок увеличивает count; в PlusButton нет $parent
// пиши здесь
Решение и объяснение
Решение изменённые строки подсвечены
const PlusButton = {
  template: '<button @click="add">+1</button>',
  methods: { add() { this.$emit('add') } },
}
const Panel = { template: '<section><slot></slot></section>' }
const component = {
  components: { PlusButton, Panel },
  data: () => ({ count: 0 }),
  template: '<div><PlusButton @add="count++" /><Panel><PlusButton @add="count++" /></Panel><span>{{ count }}</span></div>',
}
Почему так
  • Первая кнопка стоит прямо в шаблоне component — её $parent = component, count++ работает.
  • Вторая передана в слот Panel. Родитель компонента в слоте — тот, кто рендерит <slot>, то есть Panel. this.$parent.count++ превращает несуществующий count у Panel в NaN. Ошибки нет — баг тихий.
  • Исправление: кнопка генерирует событие this.$emit('add'), а владелец count подписан через @add. Так кнопка работает в любом месте дерева.
  • Правило: состоянием владеет тот, кто его объявил, — только он его и меняет. Данные идут вниз через props, события — вверх через $emit.
Коротко вслух: $parent зависит от места в дереве: в слоте родителем становится компонент со слотом. Поэтому ребёнок не меняет чужое состояние, а сообщает о событии через $emit.

Решение и объяснение
Исправление одной строкой изменённые строки подсвечены
const LangSwitch = { template: `<button @click="$root.lang = 'en'">EN</button>` }
const Greeting = { template: `<p>{{ $root.lang === 'en' ? 'Hello' : 'Привет' }}</p>` }

Как правильно — без $root изменённые строки подсвечены

new Vue({
  el: '#app',
  components: { LangSwitch, Greeting },
  data: { lang: 'ru' },
  template: '<div><LangSwitch @change="lang = $event" /><Greeting :lang="lang" /></div>',
})
Почему так
  • Здесь нужен именно корень, поэтому код — new Vue({ el }), а не component.
  • Vue 2 делает реактивными только поля, которые есть в data в момент создания. В корне lang не объявлен. $root.lang = 'en' создаёт обычное свойство без геттера и сеттера — Greeting не перерисовывается.
  • Добавить реактивное поле в корень позже нельзя. Vue.set(this.$root, 'lang', 'en') выдаст предупреждение «Avoid adding reactive properties to a Vue instance or its root $data at runtime» и значение вообще не запишет.
  • Исправление одной строкой работает, но проблемы остаются. Любой компонент может поменять $root.lang — не найти, кто это сделал. Компоненты не работают вне этого корня — в тесте или в другом приложении.
  • Правильно: состояние у общего родителя, вниз — проп, вверх — событие. В большом приложении — Vuex.
Коротко вслух: В корне не было поля lang в data, поэтому оно не реактивно. Но даже реактивный $root — это глобальная переменная без контроля: правильно передавать данные пропсами и событиями или хранить в Vuex.

Глобальная шина событий

Вопрос из списка: «Глобальная шина событий»

Суть. Глобальная шина — пустой экземпляр Vue с методами $emit/$on/$off. Через неё обмениваются событиями компоненты из любых мест дерева. Подходит для редких сообщений. От неё обязательно отписываются в beforeDestroy, событие в ней не хранится, связи становятся неявными. Во Vue 3 $on/$off/$once удалены — шину делают на библиотеке mitt.

Шина событий — отдельный пустой экземпляр Vue. Через него общаются компоненты, которые не связаны как родитель и ребёнок. Паттерн «издатель — подписчик» (publish/subscribe): один компонент отправляет событие, другие на него подписаны.

  • bus.$emit('имя', данные) — отправить событие.
  • bus.$on('имя', обработчик) — подписаться. bus.$once — подписаться на один раз.
  • bus.$off('имя', обработчик) — отписаться.

Подводные камни

  • Нет отписки — утечка и дубли. Шина живёт всё время работы приложения. Обработчики уничтоженных компонентов остаются в ней и продолжают срабатывать.
  • $off('имя') без функции снимает обработчики всех компонентов на это событие. Нужна ссылка на ту же функцию. Поэтому обработчик делают методом, а не анонимной стрелкой.
  • Событие не хранится. Если $emit случился до $on — событие потеряно. Шина передаёт сообщения, а не состояние.
  • Неявные связи. Не видно, кто отправляет и кто слушает. Имя события — строка: опечатка = тишина без ошибок.
  • Во Vue 3 $on/$off/$once удалены ($emit остался). Шину делают на библиотеке: mitt, tiny-emitter.

Порядок хуков при первом рендере — важно, когда подписываться и когда отправлять: created родителя → created детей → mounted детей → mounted родителя. Событие из created родителя дети ещё не слышат: они не подписаны.

Когда уместна. Редкие глобальные уведомления в небольшом приложении: показать тост, закрыть все модалки. Для общих данных — Vuex. Для родителя и ребёнка — props и $emit.

Пример
// bus.js — шина: пустой экземпляр Vue
export const bus = new Vue();

// отправитель
bus.$emit('login', { email: this.email });

// получатель
created() {
  bus.$on('login', this.onLogin);
},
beforeDestroy() {
  bus.$off('login', this.onLogin); // та же функция, что в $on
},
methods: {
  onLogin(user) {
    this.email = user.email;
  },
},

Решение и объяснение
Решение изменённые строки подсвечены
const bus = new Vue()
const LoginForm = {
  data: () => ({ email: 'anya@mail.ru' }),
  template: '<button @click="submit">Войти</button>',
  methods: { submit() { bus.$emit('login', this.email) } },
}
const AppHeader = {
  data: () => ({ user: 'Гость' }),
  template: '<header>{{ user }}</header>',
  created() { bus.$on('login', this.onLogin) },
  beforeDestroy() { bus.$off('login', this.onLogin) },

}
const component = {
  components: { LoginForm, AppHeader },
  template: '<div><AppHeader /><LoginForm /></div>',
}
Почему так
  • new Vue() без опций — пустой экземпляр, у которого есть $emit/$on/$off. Все, кто видит bus (в проекте — импортируют из bus.js), работают с одним списком подписчиков.
  • Подписка в created: у компонента уже есть data и методы. Отписка в beforeDestroy обязательна — иначе после уничтожения шапки обработчик останется в шине (задача 2.2).
  • Обработчик — метод, а не анонимная стрелка. Vue привязывает методы к экземпляру один раз, ссылка стабильна — её можно передать в $off.
  • Если спросят «почему не через родителя?»: когда общий родитель рядом, props и $emit лучше — их проще отлаживать. Шина — для компонентов, далёких друг от друга.
Коротко вслух: Шина — общий объект-посредник: отправитель вызывает bus.$emit, получатель подписан через bus.$on. Подписываюсь в created, отписываюсь той же функцией в beforeDestroy.

2.2 Дубли обработчиков 🟡 средний ~4 мин

Панель дважды скрыли и снова показали, и одно нажатие «Уведомить» вызывает обработчик три раза. Объясни, откуда дубли, и исправь.

Стартовый код
const bus = new Vue()
const Notices = {
  data: () => ({ count: 0 }),
  template: '<p>Уведомлений: {{ count }}</p>',
  created() { bus.$on('notify', () => { this.count++; console.log('обработчик сработал') }) },
}
const component = {
  components: { Notices },
  data: () => ({ show: true }),
  methods: { notify() { bus.$emit('notify') } },
  template: `<div><button @click="show = !show">Панель</button>
    <button @click="notify">Уведомить</button><Notices v-if="show" /></div>`,
}
// нужно: панель дважды скрыли и показали, «Уведомить» — обработчик срабатывает один раз
// пиши здесь
Решение и объяснение
Решение изменённые строки подсвечены
const bus = new Vue()
const Notices = {
  data: () => ({ count: 0 }),
  template: '<p>Уведомлений: {{ count }}</p>',
  created() { bus.$on('notify', this.onNotify) },
  beforeDestroy() { bus.$off('notify', this.onNotify) },
  methods: { onNotify() { this.count++; console.log('обработчик сработал') } },
}
const component = {
  components: { Notices },
  data: () => ({ show: true }),
  methods: { notify() { bus.$emit('notify') } },
  template: `<div><button @click="show = !show">Панель</button>
    <button @click="notify">Уведомить</button><Notices v-if="show" /></div>`,
}

Удалено из стартового кода: анонимная стрелка в bus.$on — её нельзя снять.

Почему так
  • v-if уничтожает компонент и создаёт новый. Каждый новый экземпляр в created добавляет подписку. Старые подписки никто не снял: 1 при старте + 2 после повторных показов = 3.
  • Два из трёх обработчиков принадлежат уже уничтоженным компонентам. Они держат ссылку на свой this, поэтому эти компоненты не удаляются из памяти — утечка.
  • Исправление — отписка в beforeDestroy той же функцией. Анонимную стрелку снять нельзя — на неё нет ссылки. Поэтому обработчик вынесен в метод.
  • Ловушка: bus.$off('notify') без второго аргумента снимет обработчики всех компонентов на это событие, а не только свой.

keep-alive

Вопрос из списка: «keep-alive»

Суть. <keep-alive> при переключении не уничтожает компонент, а кэширует его. Сохраняется состояние, и не тратится время на повторное создание. При уходе вместо beforeDestroy/destroyed вызывается deactivated, при возврате вместо created/mounted — activated. Кэшем управляют через include, exclude и max.

<keep-alive> — встроенный абстрактный компонент. Он кэширует неактивные экземпляры вложенного компонента вместо того, чтобы их уничтожать. Сам в DOM ничего не рендерит.

Где: вокруг <component :is>, переключения v-if/v-else, <router-view>.

Зачем: сохранить состояние (введённый текст, выбранный пункт, прокрутку внутри блока) и не пересоздавать тяжёлые компоненты с повторными запросами.

Хуки кэшируемого компонента

  • первый показ: created → mounted → activated;
  • уход: deactivated — вместо beforeDestroy/destroyed;
  • возврат: activated — без created/mounted;
  • при переключении новый компонент создаётся раньше, чем уходит старый: B created → A deactivated → B mounted → B activated.

Пропсы

  • include / exclude — кого кэшировать / не кэшировать: строка через запятую, RegExp или массив. Сравнивается с опцией name компонента, а если её нет — с тегом, как он записан в шаблоне. Регистр важен, имена через запятую пишут без пробелов.
  • max — сколько экземпляров хранить. При переполнении уничтожается тот, к которому дольше всего не обращались.

Подводные камни

  • Внутри один прямой дочерний компонент, с v-for не работает.
  • Кэш занимает память.
  • Данные могут устареть — их обновляют в activated.
  • Таймеры и глобальные слушатели останавливают в deactivated.
Пример
<!-- кэшировать только EditForm, не больше 5 экземпляров -->
<keep-alive include="EditForm" :max="5">
  <component :is="currentTab" />
</keep-alive>

<!-- то же для страниц роутера -->
<keep-alive>
  <router-view />
</keep-alive>

  • API: хуки activated / deactivated

Boolean-пропсы

Вопрос из списка: «Чем поведение prop’а с типом Boolean отличается от остальных?»

Суть. Для пропа типа Boolean Vue делает особое приведение. Не передан и нет default — false, а не undefined. Атрибут без значения или со значением, равным имени пропа в kebab-case (is-open="is-open"), — true. Без двоеточия значение — всегда строка: visible="false" — это truthy-строка "false". Логическое значение передают через :visible="false".

У пропа с типом Boolean особое приведение значения — как у HTML-атрибутов вроде <input disabled>: есть атрибут — значит, true.

В шаблонеdisabled: Booleanlabel: String

<Btn disabled="disabled" /> — значение = имяtrueстрока как есть

<Btn :disabled="false" /> — через v-bindfalse—
  • Главное правило. Без : значение атрибута — всегда строка. Логическое значение передают через v-bind: :disabled="false", :disabled="isLoading".
  • Только для типа Boolean. Проп без типа (props: ['visible']) приведения не получает: <X visible /> даст пустую строку, а она falsy.
  • Имя в kebab-case. Из значений, совпадающих с именем, в true превращается только имя в kebab-case: is-open="is-open". Запись is-open="isOpen" — просто строка.
  • Несколько типов. Приведение '' → true работает, только если Boolean стоит раньше String: при [Boolean, String] <Icon a /> даёт true, при [String, Boolean] — пустую строку.
  • По умолчанию включено. { type: Boolean, default: true } — если проп не передан, будет true.
Пример

  disabled: Boolean,                          // не передан → false
  closable: { type: Boolean, default: true }, // «по умолчанию включено»

},
<Btn disabled />            <!-- true -->
<Btn :disabled="false" />   <!-- false: значение — выражение JS -->
<Btn disabled="false" />    <!-- строка 'false' + предупреждение Vue -->

Как убрать реактивность

Вопрос из списка: «Как убрать реактивность у объекта?»

Суть. Vue 2 не делает реактивным замороженный объект: в this.list = Object.freeze(data) поле list реактивно, а содержимое — нет. Менять такие данные можно только заменой целиком. Второй способ — не объявлять свойство в data, а задать его в created или mounted: это обычное свойство, его изменения не вызывают перерисовку.

Когда объект попадает в data, Vue 2 рекурсивно обходит его. Каждое свойство он превращает в геттер/сеттер (Object.defineProperty) и вешает на объект наблюдателя __ob__. У массивов геттеров на индексы нет: Vue подменяет их методы push, splice и другие. Для больших данных — тысяч строк, справочников — это заметные время и память.

Если данные только показываются и не меняются по частям, реактивность внутри не нужна.

Способы

  • Object.freeze(obj) перед присвоением. Vue видит, что объект нерасширяемый (Object.isExtensible = false), и не обходит его. Само поле, например this.items, остаётся реактивным: присвоение нового значения целиком перерисует компонент.
  • Не объявлять в data. this.chart = new Chart(...) в created/mounted — обычное свойство, Vue о нём не знает. Подходит для экземпляров сторонних библиотек, таймеров, кэшей.
  • Константа вне компонента — если данные не меняются вообще.
  • Vue 2.7 и Vue 3: markRaw(obj), а также shallowRef и shallowReactive из Composition API.

Важно

  • freeze неглубокий: вложенные объекты не заморожены. Но Vue 2 внутрь замороженного не заходит, так что реактивными они тоже не станут.
  • Изменить замороженное можно только заменой целиком: this.items = Object.freeze(newItems). push бросит TypeError.
  • Замораживают до присвоения в data. Object.freeze уже реактивного объекта реактивность не снимает: геттеры и сеттеры уже созданы и работают.
  • Нужна обычная, нереактивная копия реактивных данных (например, отправить на сервер) — JSON.parse(JSON.stringify(obj)) для простых данных.
  • Нереактивное ≠ невидимое. Значение покажется, если компонент перерисуется по другой причине.
  • Как проверить: у реактивного объекта есть __ob__, а в DevTools его поля показаны как (...) — это геттеры.
Пример
data() {
  return { cities: [] };
},
async created() {
  const list = await api.getCities();
  this.cities = Object.freeze(list); // поле cities реактивно, содержимое — нет
},
mounted() {
  this.chart = new Chart(this.$el); // не объявлено в data → обычное свойство
},
methods: {
  rename(id, name) {
    // замороженное меняем только заменой целиком
    this.cities = Object.freeze(
      this.cities.map((c) => (c.id === id ? { ...c, name } : c))

  },

6

Virtual DOM

Вопрос из списка: «Что такое virtual-dom, как он работает и для чего нужен?»

Суть. Virtual DOM — дерево обычных JS-объектов (VNode), которое описывает, каким должен быть DOM. Шаблон компилируется в render-функцию, она возвращает это дерево. При изменении данных Vue строит новое дерево, сравнивает со старым и вносит в реальный DOM только отличия. Так можно писать UI декларативно и не трогать DOM вручную.

Virtual DOM (VDOM) — дерево лёгких JS-объектов (VNode), которое описывает, каким должен быть реальный DOM. VNode — просто объект: тег, атрибуты, дети, key.

Как работает во Vue

  1. Компиляция. Шаблон превращается в render-функцию — при сборке (vue-loader) или в браузере (полная сборка Vue с компилятором). Render возвращает дерево VNode.
  2. Монтирование. Vue обходит дерево VNode и создаёт реальные DOM-узлы.
  3. Обновление (patch / diff). Изменились реактивные данные → render вызывается заново → новое дерево → сравнение со старым → в DOM вносятся только отличия.

Как сравнивает (упрощённо)

  • Сравнивает узлы одного уровня, а не всё дерево целиком.
  • Узлы считаются одинаковыми, если совпадают тег и key (у input ещё и type). Тогда DOM-элемент переиспользуется, меняются только атрибуты, текст, дети.
  • Разный тег или key — старый узел удаляется, новый создаётся. Компонент внутри пересоздаётся: снова created/mounted.
  • Без key одинаковыми считаются узлы с тем же тегом. Для списка это значит правку «на месте» по порядку.
  • Поэтому key = индекс — плохо: при вставке или удалении в середине индексы сдвигаются, и Vue переиспользует чужие узлы. Введённый текст и состояние дочерних компонентов «переезжают» к соседу.

Зачем. Операции с реальным DOM дорогие: пересчёт стилей и раскладки. VDOM позволяет писать декларативно («каким должен быть UI»), а Vue сам вычисляет минимальные изменения. Дерево VNode можно отрендерить не только в DOM — например, в строку на сервере (SSR).

Нюансы. Во Vue перерисовывается только компонент, чьи данные изменились, а не всё приложение. VDOM не «быстрее DOM»: он быстрее наивного «перерисовать всё через innerHTML» и удобнее ручных правок.

Пример
// шаблон <div id="app"><p>{{ msg }}</p></div> компилируется в render-функцию:
render(h) {
  return h('div', { attrs: { id: 'app' } }, [h('p', this.msg)]);
}

// render возвращает не DOM, а дерево VNode — обычных объектов (упрощённо):
{
  tag: 'div',
  data: { attrs: { id: 'app' } },
  children: [{ tag: 'p', children: [{ text: 'Привет' }] }],
}

Решение и объяснение
Решение изменённые строки подсвечены

  • Vue сравнивает новый VNode со старым VNode, а не с реальным DOM. О классе, добавленном через classList, он не знает.

Коротко вслух: Vue сравнивает виртуальные деревья между собой, а не с реальным DOM. Ручная правка не попадает в VNode и стирается при следующем обновлении этого атрибута.

nextTick и setTimeout

Вопрос из списка: «nextTick(): для чего нужен и когда использовать? Чем отличается от setTimeout()?»

Суть. Vue обновляет DOM не сразу после изменения данных, а пачкой в ближайшей микрозадаче. $nextTick выполняет код сразу после этого обновления — например, чтобы поставить фокус на появившееся поле или измерить элемент. setTimeout — макрозадача: сработает позже, после всех микрозадач, часто уже после отрисовки кадра, и к очереди Vue не привязан.

Vue обновляет DOM не сразу. Изменили данные → watcher компонента попадает в очередь (дубли отбрасываются) → очередь выполняется асинхронно, в микрозадаче (Promise.then) → DOM обновлён. Поэтому сразу после this.x = 1 в DOM ещё старое значение.

Зачем пачкой: три изменения подряд → одна перерисовка с итоговыми значениями, а не три.

$nextTick — выполнить код после того, как Vue применит изменения к DOM. Две формы: this.$nextTick(cb) и await this.$nextTick(). Глобально — Vue.nextTick.

Когда нужен

  • поставить фокус на поле, которое только что появилось через v-if;
  • измерить размер или позицию элемента после изменения данных;
  • прокрутить чат вниз после нового сообщения;
  • инициализировать стороннюю библиотеку на обновлённом DOM.

Нюанс. nextTick — это очередь в порядке регистрации. Колбэк, поставленный до первого изменения данных в этом тике, выполнится до обновления DOM.

Решение изменённые строки подсвечены

Почему data — функция

Вопрос из списка: «Почему data в компоненте vue должна быть функцией?»

Суть. Описание компонента одно на все экземпляры. Если бы data был объектом, все экземпляры делили бы одну ссылку, и изменение в одном меняло бы все. Функция вызывается для каждого экземпляра и возвращает новый объект — у каждого своё состояние. В корневом new Vue() объект допустим: экземпляр один.

Описание компонента — шаблон для многих экземпляров. Каждый <Counter /> создаётся по одному и тому же объекту опций.

  • Если бы data был объектом, все экземпляры получили бы ссылку на один и тот же объект. Клик по одному счётчику менял бы все.
  • Функция вызывается для каждого экземпляра заново и возвращает новый объект — у каждого своё состояние.
  • Если в компоненте написать data: { ... }, Vue 2 выдаст предупреждение «The "data" option should be a function…» и проигнорирует такие данные.
  • В корневом new Vue({ data: {...} }) объект допустим — экземпляр один.
  • Бонус: внутри функции доступен this с уже готовыми props. Начальное состояние можно взять из пропа: data() { return { count: this.start } }.
  • Ловушка. Функция не спасает, если возвращает общий объект — переменную снаружи или вложенную ссылку на общий объект. Нужен новый объект или копия.
Пример
// плохо: объект — Vue 2 выдаст предупреждение и проигнорирует data
data: { count: 0 },

// плохо: функция, но возвращает общий объект
const state = { count: 0 };
data() { return state; },

// хорошо: новый объект при каждом вызове, можно брать начальные значения из props
data() {
  return { count: this.start, filters: { ...DEFAULT_FILTERS } };
},

Миксины

Вопрос из списка: «Mixin: для чего нужны? Как создать?»

Суть. Миксин — объект с опциями компонента: data, methods, computed, хуки. Его подключают через mixins: [...], чтобы переиспользовать одинаковую логику в нескольких компонентах. Опции сливаются: хуки вызываются все (сначала миксина), а в data и methods при конфликте побеждает компонент. Минусы — неявное происхождение свойств и молчаливые конфликты имён.

Миксин — обычный объект с опциями компонента (data, computed, methods, watch, хуки). Подключается через mixins: [myMixin], и его опции сливаются с опциями компонента.

Зачем: переиспользовать одинаковую логику в разных компонентах — флаг загрузки, пагинация, «открыть/закрыть», подписка на resize.

Как сливаются опции

ОпцияПравило
dataобъединяются рекурсивно; при конфликте побеждает компонент
хуки (created, mounted…)вызываются все: сначала миксина, потом компонента
watchвызываются все: сначала миксина
methods, computed, components, directivesобъединяются; при одинаковом ключе побеждает компонент — молча
  • Несколько миксинов применяются по порядку массива, компонент — последним.
  • Глобальный миксин Vue.mixin({...}) попадает в каждый компонент, включая сторонние. Использовать крайне осторожно.
  • Минусы: не видно, откуда в компоненте взялось this.loading; конфликты имён без ошибок; неявные зависимости — миксин ждёт, что в компоненте есть this.fetchData.
  • Альтернатива. Во Vue 2.7 и Vue 3 вместо миксинов рекомендуют composables — функции use… внутри setup. Миксины во Vue 3 по-прежнему работают.
Пример
// mixins/toggle.js
export const toggle = {
  data() {
    return { isOpen: false };
  },
  methods: {
    open() { this.isOpen = true; },
    close() { this.isOpen = false; },
  },
  created() {
    console.log('хук миксина'); // вызовется раньше хука компонента
  },
};

// Modal.vue
import { toggle } from './mixins/toggle';

export default {
  mixins: [toggle],
  created() {
    console.log('хук компонента');
  },
};

  mixins: [logMixin],

  created() { console.log('created компонента:', this.hello()) },
  mounted() { console.log(this.msg, this.level) },
  methods: { hello() { return 'hello компонента' } },
  template: '<p></p>',
}
// пиши здесь: что выведут 3 строки?
Решение и объяснение
Ответ
created миксина: из компонента
created компонента: hello компонента
из компонента 1
Почему так
  • data слились: msg есть в обоих — взят из компонента; level только в миксине — добавился.
  • created вызваны оба: хуки собираются в массив, миксин первым. Но data к этому моменту уже общая, слитая. Поэтому хук миксина видит msg компонента.
  • methods: одинаковое имя — метод компонента заменил метод миксина. Без ошибок и предупреждений.
Коротко вслух: Хуки из миксина и компонента вызываются все, миксин первым. В data, methods и computed при совпадении ключей побеждает компонент.

9.3 Конфликт имён 🟡 средний ~4 мин

Компонент подключил миксин пагинации и написал свой next() для шагов. «Следующая страница» перестала листать страницы. Объясни, что произошло, и исправь так, чтобы работали обе кнопки.

Стартовый код
const paginationMixin = {
  data: () => ({ page: 1 }),
  methods: { next() { this.page++ } },
}
const component = {
  mixins: [paginationMixin],
  data: () => ({ step: 1 }),
  methods: { next() { this.step++ } },
  template: `<div><button @click="next">Следующая страница</button>
    <button @click="next">Следующий шаг</button>
    <p>страница {{ page }}, шаг {{ step }}</p></div>`,
}
// нужно: каждая кнопка меняет своё — страницу или шаг
// пиши здесь
Решение и объяснение
Решение изменённые строки подсвечены
const paginationMixin = {
  data: () => ({ page: 1 }),
  methods: { nextPage() { this.page++ } },
}
const component = {
  mixins: [paginationMixin],
  data: () => ({ step: 1 }),
  methods: { nextStep() { this.step++ } },
  template: `<div><button @click="nextPage">Следующая страница</button>
    <button @click="nextStep">Следующий шаг</button>
    <p>страница {{ page }}, шаг {{ step }}</p></div>`,
}
Почему так
  • methods миксина и компонента сливаются в один объект. Одинаковое имя — побеждает компонент. Vue не предупреждает.
  • В итоге обе кнопки вызывают next компонента — листается шаг, а не страница.
  • Исправление — уникальные имена. Члены миксина называют конкретно (nextPage, paginationReset), чтобы они не пересекались с компонентом. Style guide Vue советует для приватных методов миксинов префикс вида $_pagination_.
  • Это главный минус миксинов — неявные конфликты. Composables (Vue 2.7 и Vue 3) решают его: имена задаёт сам компонент при деструктуризации.
Коротко вслух: Методы миксина и компонента сливаются, и при совпадении имени метод миксина молча перезаписывается. Поэтому у членов миксина должны быть уникальные, «говорящие» имена.

10

watch: deep и immediate

Вопрос из списка: «Watch: для чего нужен? deep, immediate.»

Суть. watch выполняет побочное действие при изменении данных: запрос, запись в localStorage, работу с библиотекой. Для значений, вычисляемых из других данных, нужен computed. immediate: true вызывает обработчик сразу при создании компонента. deep: true реагирует на изменения внутри объекта, а не только на его замену.

watch — реакция на изменение данных побочным действием: запрос к API, сохранение в localStorage, логирование, работа со сторонней библиотекой. Особенно для асинхронных и дорогих операций, например поиска с debounce.

Если нужно получить значение из других данных — это computed, а не watch.

  • immediate: true — вызвать обработчик сразу при создании компонента (ещё до created) с текущим значением. oldVal при этом undefined. Избавляет от дублирования вызова в created.
  • deep: true — следить за изменениями на любой глубине внутри объекта. Без deep watch реагирует на замену объекта и на добавление или удаление ключей через Vue.set/Vue.delete, но не на изменение существующих полей. У массивов push/splice ловятся и без deep, а изменения полей объектов внутри массива — только с deep.
  • При изменении внутри объекта (а не замене) newVal === oldVal: это одна и та же ссылка, копию «до» Vue не хранит.
  • deep на большом объекте дорогой. Лучше следить за конкретным полем: 'form.email'.
  • Обработчик — обычная функция, не стрелочная, иначе this не будет компонентом.
  • Обработчик вызывается асинхронно и один раз на все изменения за тик — с последним значением.
  • В обработчике DOM ещё старый: watch вызывается до перерисовки. Нужен новый DOM — await this.$nextTick() внутри обработчика.
Пример
watch: {
  // 1. функция: (новое, старое)
  query(newVal, oldVal) {
    this.search(newVal);
  },
  // 2. имя метода
  userId: 'loadUser',
  // 3. путь через точку — одно вложенное поле
  'form.email'(email) {
    this.validate(email);
  },
  // 4. объект с опциями
  filters: {
    handler(val) {
      this.load(val);
    },
    deep: true,      // реагировать на изменения внутри объекта
    immediate: true, // вызвать сразу при создании компонента
  },
},

// императивно — возвращает функцию отписки
const unwatch = this.$watch('query', this.search, { immediate: true });
unwatch();

10.1 Загрузка при старте 🟢 базовый ~3 мин

Компонент загружает пользователя при смене пропа userId, но при первом показе ничего не загружается. Исправь, не дублируя вызов в created.

Стартовый код
const UserCard = {
  props: ['userId'],
  watch: { userId(id) { console.log('загружаю пользователя', id) } },
  template: '<p>id: {{ userId }}</p>',
}
const component = {
  components: { UserCard },
  data: () => ({ id: 1 }),
  template: '<div><UserCard :user-id="id" /><button @click="id++">Следующий</button></div>',
}
// нужно: при показе — «загружаю пользователя 1», после клика — «… 2»; без вызова в created
// пиши здесь
Решение и объяснение
Решение изменённые строки подсвечены
const UserCard = {
  props: ['userId'],
  watch: {
    userId: {
      handler(id) { console.log('загружаю пользователя', id) },
      immediate: true,
    },
  },
  template: '<p>id: {{ userId }}</p>',
}
const component = {
  components: { UserCard },
  data: () => ({ id: 1 }),
  template: '<div><UserCard :user-id="id" /><button @click="id++">Следующий</button></div>',
}
Почему так
  • Обычный watch реагирует только на изменения после создания. Начальное значение 1 изменением не считается — вызова нет.
  • immediate: true вызывает обработчик сразу при создании watcher — в фазе инициализации, ещё до created — с текущим значением. oldVal при этом undefined.
  • Без immediate пришлось бы вызывать загрузку и в created, и в watch — дублирование. Immediate делает то же одной опцией.
Коротко вслух: Watch по умолчанию реагирует только на последующие изменения. immediate: true вызывает обработчик сразу при создании с текущим значением.

10.2 Изменение внутри объекта 🟡 средний ~4 мин

Черновик формы должен сохраняться при каждом изменении полей, но при вводе email сохранения нет. Исправь наблюдатель и объясни, почему в логе newVal === oldVal.

Стартовый код
const component = {
  data: () => ({ form: { email: '', name: '' } }),
  watch: {
    form(newVal, oldVal) { console.log('сохраняю', JSON.stringify(newVal), newVal === oldVal) },
  },
  template: '<input v-model="form.email" placeholder="email">',
}
// нужно: при вводе a@b.ru → сохраняю {"email":"a@b.ru","name":""} true
// пиши здесь
Решение и объяснение
Решение изменённые строки подсвечены
const component = {
  data: () => ({ form: { email: '', name: '' } }),
  watch: {
    form: {
      handler(newVal, oldVal) { console.log('сохраняю', JSON.stringify(newVal), newVal === oldVal) },
      deep: true,
    },
  },
  template: '<input v-model="form.email" placeholder="email">',
}
Почему так
  • Без deep watcher на form срабатывает при замене объекта и при добавлении или удалении ключей через Vue.set/Vue.delete. v-model меняет существующее поле form.email — watcher молчит.
  • deep: true — Vue обходит все вложенные поля и подписывается на каждое. Любое изменение внутри запускает обработчик.
  • newVal === oldVal → true: объект изменён, а не заменён. Обе переменные указывают на один объект, копию «до» Vue не хранит.
  • Также можно следить за одним полем: 'form.email'(newVal, oldVal) {…}. Подписка дешевле, и oldVal настоящий. Но изменение name такой watcher не заметит — для черновика всей формы его мало.
Коротко вслух: Без deep watch следит только за заменой объекта. deep подписывается на все вложенные поля, но newVal и oldVal — одна и та же ссылка. Если нужно одно поле, дешевле следить за путём form.email.

10.3 watch → computed 🟢 базовый ~3 мин

Полное имя собирается двумя обработчиками watch. Перепиши на computed с тем же поведением и объясни, когда нужен watch, а когда computed.

Стартовый код
const component = {
  data: () => ({ firstName: 'Анна', lastName: 'Иванова', fullName: 'Анна Иванова' }),
  watch: {
    firstName(val) { this.fullName = val + ' ' + this.lastName },
    lastName(val) { this.fullName = this.firstName + ' ' + val },
  },
  template: `<div><p>{{ fullName }}</p><button @click="lastName = 'Петрова'">Сменить фамилию</button></div>`,
}
// нужно: то же поведение без watch — после клика «Анна Петрова»
// пиши здесь
Решение и объяснение
Решение изменённые строки подсвечены
const component = {
  data: () => ({ firstName: 'Анна', lastName: 'Иванова' }),
  computed: {
    fullName() { return this.firstName + ' ' + this.lastName },
  },
  template: `<div><p>{{ fullName }}</p><button @click="lastName = 'Петрова'">Сменить фамилию</button></div>`,
}

Удалено из стартового кода: поле fullName из data и весь watch.

Почему так
  • Было: fullName — отдельное состояние, которое вручную синхронизируют два обработчика. Начальное значение продублировано. Добавится третье поле, например отчество, — придётся писать третий watch.
  • computed описывает зависимость декларативно. Vue сам знает, что fullName зависит от firstName и lastName, пересчитывает и кэширует результат.
  • Поле fullName из data нужно удалить: одно имя не может быть и в data, и в computed. Иначе Vue выдаст «The computed property "fullName" is already defined in data», а на экране останется старое значение.
  • watch — для побочных эффектов: запрос к API, запись в localStorage, таймеры, работа с DOM и библиотеками. computed — для значений, выводимых из других данных, без побочных эффектов.
Коротко вслух: Если значение вычисляется из других данных — это computed: он декларативный и кэшируется. Watch — когда на изменение нужно сделать побочное действие.
